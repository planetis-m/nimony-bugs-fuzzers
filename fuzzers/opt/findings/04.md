# 04 — (out of phase, frontend) nimsem crashes in `inferle.implies` on `x <= 0xFFFFFFFFFFFFFFFF'u64`

Kind: **crash** (compiler aborts on a valid program; `nimony check` is enough). Default contract
mode, no pragmas. Found incidentally: the native worker's base build of seed 900203 crashed; the
same program crashes `nimony c` too. Known-as: **new trigger** of the assertion seen in the closed
nim-lang/nimony#2672 and #2535 (different shape: a uint64 comparison with the all-ones constant;
those were int subtraction chains). Not in bug-reports.

## Minimized repro (`old/min/inf7.nim`)
```nim
proc t0(x, y: uint64): bool =
  if x <= 0xFFFFFFFFFFFFFFFF'u64:
    result = x > y
```

## Command
```
nimony check inf7.nim        (or nimony c / nimony n)
```

## Actual
```
assertions.nim(38)       raiseAssert
Error: unhandled exception: inferle.nim(279, 3) `v.isValid`  [AssertionDefect]
```
## Expected
Accepted (the program is trivially valid). With `x < 0x8000000000000000'u64` instead it is accepted.

## Phase at fault
nimsem's fact engine `src/nimony/inferle.nim`, `implies` (`assert v.isValid`; `isValid` requires
`not isNaN(x.c)`): the guard `x <= 0xFFFF_FFFF_FFFF_FFFF` yields a fact whose constant does not fit
the signed `xint` (NaN), and the later `x > y` query built from it is handed to `implies` invalid.
The caller that turns a comparison into a `LeXplusC` should drop facts whose constant is NaN.
