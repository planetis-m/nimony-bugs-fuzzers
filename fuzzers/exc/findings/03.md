# 03 — `defer` inside a branch of an `if`/`case`/`try` EXPRESSION corrupts the tree

kind: **crash**. known-as: **new** (upstream #2400 is `defer` + `return <expr>`, closed, different; nothing in bug-reports).

## Repro (min/f03c.nim)
```nim
import std/syncio

proc t(v: int) =
  let a = if v > 0:
      defer: echo "leaving branch"
      v
    else:
      0
  echo a

t(1)
```
Also in a `case` expression branch (min/f03b.nim) and in a try-expression body (min/f03.nim).
Command: `bin/nimony c -r --nimcache:nc min/f03c.nim` (same on `n`).
Actual: `Error: unhandled exception: nimony_model.nim(295, 3) n.isTagLit [AssertionDefect]`. Fuzzer variants
of the same shape also died with `[Bug] could not find symbol: l17.0`, `[Bug] call must have been bound to a
location` (finalir.nim:177) and a bare `[AssertionDefect]`.
Expected: `leaving branch` then `1` (the branch is a scope; the defer runs when it ends) — or a clean
"defer not allowed here" error.

## Phase / function
`src/nimony/deferstmts.nim`: `trBlock` deliberately does NOT open a scope for an expression branch (anything
that is not `(stmts)`/`(scope)`) and calls `trStmt` on it, so the `defer` inside `(expr (defer …) v)` is
recorded by `trDefer` against the ENCLOSING statement scope, at a position inside the expression. At that
scope's end `wrapOneDefer` cuts `dest[startsAt..]` — the middle of the `let`'s value through the scope's end —
and re-emits it wrapped in `(try (stmts …) (fin …))`, producing an ill-formed tree.
Found within the first 2 minutes; 5 of the first 8 signatures. The generator now keeps `defer` out of
expression branches (`noexprdefer`).
