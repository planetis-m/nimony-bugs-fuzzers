# 01 — `raise` as a branch of an `if`/`case` expression crashes xelim (`cannot compute type of`)

kind: **crash** (valid program, compiler assertion). known-as: **new** (no bug-reports match; upstream searches "cannot compute type", "raise if expression" empty).

## Repro (min/f01.nim)
```nim
import std/syncio
proc t(v0: int) {.raises.} =
  let a = if v0 == 2: 4 else: raise ValueError
  echo a
try: t(3) except ErrorCode as e: echo "U ", e
```
Also `let a = case v of 2: raise ValueError else: 4` (min/f01b.nim), `result = if c: raise ValueError else: 4`,
and the same with a `ref` exception (`raise E1(msg: "q")`). `quit(1)` in the same position compiles fine.

Command: `bin/nimony c -r --nimcache:nc min/f01.nim` (same on `n`).

Actual: `Error: unhandled exception: xelim.nim(118, 3) result.typeKind != AutoT cannot compute type of: (expr ...` (nimsem dies).
Expected: prints `4` (a raising branch is a noreturn branch; the expression's type comes from the other branch).

## Phase / function
`src/hexer/xelim.nim` `getType` asserts; root is `src/nimony/typenav.nim` `getTypeImpl` for `IfS`/`CaseS`:
it picks "the first non-void branch type", and a `(raise …)` branch body types as `autoType` (getTypeImpl's
error default), not void, so `auto` wins. A noreturn `raise` branch should be skipped like a void one
(a call to a `noreturn` proc such as `quit` already types void, which is why that works).
Found by the generator's `p_raise_branch` option (now off by default because every program hit it).
