# 02 — try-EXPRESSION whose body raises a `ref` exception drops the `except` branch value

kind: **rejects-valid** (prover error on a valid program) and **crash** (lengc "statement expected") depending on context.
known-as: **new** (no bug-reports match; upstream "try expression ref", "has been initialized try" give nothing related).

## Repro (min/f02.nim)
```nim
import std/syncio
type
  E1 = ref object of Exception

proc f(x: int): int {.raises: E1.} =
  if x == 0: raise E1(msg: "zero")
  result = x

proc t(v: int): int =
  result = (try: f(v) except: v + 3)

echo t(1)
echo t(0)
```
Command: `bin/nimony c -r --nimcache:nc min/f02.nim` (same on `n`).
Actual: `f02.nim(10, 11) Error: cannot prove that `x has been initialized` (`` `x`` is xelim's temp).
Expected: `1` then `3`. The identical program with `{.raises.}`/ErrorCode compiles and runs.

Variant (min/f02b.nim): `let o = O(c: (try: f(v) except: 3))` -> `[Error] statement expected, but got: 3`
from lengcgen; with an arithmetic branch (`except: v + 3`) shoggoth reports `unknown statement: (bitand …)`.
Other fuzzer hits with the same root: `let x = try: … except E2: … except E1: …` in any `.raises: E1` routine.

## Phase / function
Final IR (`--verbose`) shows the except body as
`(stmts (let `err = exc) (asgn exc nil) (stmts (add v 3)))` — the value `v + 3` is never assigned to `` `x.0``.
The wrapper comes from `src/nimony/derefs.nim` `emitDispatcher` (the ref-exception except dispatcher:
`let err = exc; exc = nil; if instanceof … elif … else …`). It emits the arms as STATEMENT bodies
(`StmtsS`/`IfS`) even when the `try` is an expression, so xelim (and the prover's init check) see a void
handler. Same mistake `deferstmts.trBlock`'s comment describes for if/case expressions. Fix: when the `try` is
an expression, emit the dispatcher as an `(expr …)` whose `if` branches keep their values.
