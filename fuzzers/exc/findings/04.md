# 04 — A raise from a `finally` on a `return`/`break` path is caught by the same `try`'s own `except`; the finally then runs twice

kind: **miscompile** (all backends, with and without `--opt:speed`). known-as: **new** (nothing in
bug-reports; upstream "finally raise except", "finally twice" give nothing; prover finding 08 is a different, prover-only issue).

## Repro (min/f04.nim)
```nim
import std/syncio

proc t() {.raises.} =
  try:
    echo "body"
    return
  except:
    echo "except arm (must not run)"
  finally:
    echo "fin"
    raise SyntaxError

try:
  t()
except ErrorCode as e:
  echo "U ", e
```
Command: `bin/nimony c -r --nimcache:nc min/f04.nim` (also `c --opt:speed`, `n`).
Actual:
```
body
fin
except arm (must not run)
fin
U SyntaxError
```
Expected: `body`, `fin`, `U SyntaxError` — an exception raised in `finally` leaves the `try`, its own
handlers do not see it (the eraiser's own comment: "a raise inside it propagates PAST this `try`").
Same with `break` out of a loop (min/f04b.nim), with a raising CALL in the finally (min/m06.nim), and with
`ref` exceptions (`except E3` + `raise E3(...)` in finally). Without the `return`/`break` it is correct.

## Phase / function
`src/hexer/eraiser.nim` `replicateFin` (called from `emitFinsDownTo` by `trRet`, `trJmp`, `emitUnwind`).
When a `return`/`break` leaves the try, the finally body is copied at the exit site while the `try`'s
`ExitScope` frame is still on `c.exits`; `replicateFin` only detaches the frame's `fin` (to stop infinite
replication) but leaves its catch `label`, so `catchingFrame` inside the copy finds this very `try` and the
raise becomes `jmp exlab` into its own handler, which then runs its finally copy again. `trTry` gets this right
for the fall-through path by popping the frame before `emitFinCopy`; `replicateFin` should likewise hide
frames `idx..^1` (e.g. temporarily truncate `c.exits` to `idx`) while emitting the copy.
4 of the first 5 reduced mismatches were this bug; the generator now avoids raising inside `finally` (`nofinraise`).

Also reached through a `defer` whose body raises, enclosing a `try: return except: …` (fuzzer hit
db466bff62b2): the defer's finally copy is emitted while the INNER try's frame is still on the stack, so the
raise lands in the inner `except` arm the `return` had already left.
