# 05 — `return`/`break`/`continue` in an outer `finally` re-runs the inner `finally` the jump already ran

kind: **miscompile** (all backends; no exceptions involved). known-as: **new** (nothing in bug-reports or upstream
for "finally twice"). Same function as 04 (`eraiser.replicateFin`), different trigger — one fix covers both.

## Repro (min/f04c.nim)
```nim
import std/syncio

proc t() =
  try:
    try:
      return
    finally:
      echo "inner finally"
  finally:
    return

t()
```
Command: `bin/nimony c -r --nimcache:nc min/f04c.nim` (same with `n`, `--opt:speed`).
Actual: `inner finally` printed twice. Expected: once.
Loop form (min/f04d.nim: `break` in the inner try, `continue` in the outer finally, 2 iterations):
prints `inner finally` 4 times instead of 2. Also with `defer` as the inner finally (fuzzer hit e9122a00c2a9:
`try: (defer: echo …; return) finally: return` inside a `finally`).

## Phase / function
`src/hexer/eraiser.nim` `trRet`/`trJmp` -> `emitFinsDownTo` -> `replicateFin`. The `return` in the inner `try`
replicates the inner finally, then the outer finally; the outer copy contains its own `return`, whose `trRet`
calls `emitFinsDownTo(c, dest, 0)` again. `replicateFin` detached only the OUTER frame's `fin`; the inner
frame (already being left) is still on `c.exits` with its `fin`, so it is copied a second time. While copying
frame `idx`'s finally, frames `idx+1..^1` must be invisible (both their `fin` and their catch `label` — the
latter is bug 04).
