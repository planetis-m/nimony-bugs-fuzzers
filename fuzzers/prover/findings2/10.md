# 10 — `addr p[].x`, `addr n[].x` and `addr p[]` are rejected: "invalid expression for `addr` operation"

kind: **rejects-valid**. known-as: **new** (nimony#840 is a different `addr` case, `addr varret(x)`, closed;
nothing in the trackers). Found by the func-rule generator (68 log lines: every `let q = addr <path>` whose path
contains an explicit `[]` dereference, in `proc`s and `func`s alike).

## Minimized repro (`repro/r10_addr_deref_field.nim`)

```nim
import std/syncio
type
  Obj = object
    x: int
  Node = ref Obj
proc viaDot(n: Node): ptr int = addr n.x        # accepted
proc viaDeref(n: Node): ptr int = addr n[].x    # Error
proc viaPtr(p: ptr Obj): ptr int = addr p[].x   # Error
proc whole(p: ptr Obj): ptr Obj = addr p[]      # Error
let n = Node(x: 1)
viaDeref(n)[] = 5
echo n.x
```

Command: `bin/nimony c -r --nimcache:nc r10_addr_deref_field.nim`

Actual:
```
r10_addr_deref_field.nim(7, 43) Error: invalid expression for `addr` operation: n[].x
r10_addr_deref_field.nim(8, 44) Error: invalid expression for `addr` operation: p[].x
r10_addr_deref_field.nim(9, 40) Error: invalid expression for `addr` operation: p[]
```

Expected: accepted (prints `5`); `n[].x` is the same location as `n.x`, which is accepted. doc/language.md,
"The addr operator": "The `addr` operator returns the address of an l-value." A dereference is an l-value.

## Phase / function at fault

`src/nimony/semmagics.nim: semAddr` -> `src/nimony/derefs.nim: isAddressable` -> `rootOf(n, allowIndirection =
true)`: the walk accepts `DotX, AtX, ArratX, TupatX, ParX` and, with indirection, `PatX, DdotX` (`n.x` is a
`DdotX`), but not `DerefX` (`n[]`), so `rootOf` returns `NoSymId`; the fallback loop in `isAddressable` has no
`DerefX` arm either.

Fix risk: low (add `DerefX`/`HderefX` beside `PatX, DdotX` in the `allowIndirection` arm).
