# 12 — incomplete-vs-spec: the callee's `ensures` about a `var` parameter does not hold for the argument after the call

kind: **rejects-valid** (spec conformance, low priority; the aliasing spec is not implemented yet). known-as: new
(not in the trackers; fuzzers#24 is a different set of rejections). Found by `specgen.py`
(findings2/spec-matrix.csv).

## Minimized repro (`repro/r12_var_ensures.nim`)

```nim
{.feature: "staticContracts".}
import std/syncio
func setPos(x: var int) {.ensures: x >= 0.} =
  if x < 0: x = 0
func setPos2(x: var int) {.ensures: x >= 0.} =
  x = 5
func retPos(x: int): int {.ensures: result >= 0.} =
  if x < 0: return 0
  return x
proc t1(a: int) =
  var i = a
  setPos(i)
  {.assert: i >= 0.}          # cannot prove
proc t2(a: int) =
  var i = a
  setPos2(i)
  {.assert: i >= 0.}          # cannot prove
proc t3(a: int) =
  var i = a
  var y = a
  if i >= 0 and i < 4:
    setPos(y)
    {.assert: i < 4.}         # proved
proc t4(a: int) =
  let i = retPos(a)
  {.assert: i >= 0.}          # proved: `ensures` about `result` is used
t1(1); t2(1); t3(1); t4(1)
```

Command: `bin/nimony c --nimcache:nc r12_var_ensures.nim`

Actual:
```
r12_var_ensures.nim(13, 5) Error: cannot prove assertion: 0 <= i
r12_var_ensures.nim(17, 5) Error: cannot prove assertion: 0 <= i
```
(the callees' own `ensures` are proved; the same for a `proc` callee).

Expected: accepted. doc/language.md, Aliasing: "Passing it as `var` is such a write; afterwards what the callee's
`ensures` states about it holds."

## Spec matrix (rest of the characterization)

Every owned-variable fact (local, `result`, non-`var` param, `s.len` of a non-`var` seq param, local seq len,
local object field, a local copy of a global as in the doc example, `let`) is proved across every statement the
spec lists — proc calls, `log("x")`, method call, routine value, closure call, store through `gp`, stores to
globals and to `var` params, `func` calls on other variables, `inc`, `add`. The prover keeps more than the spec
allows (finding 11), so nothing is lost there. The rejections are all about the variable the call writes:
`ls.add 1` drops `a < ls.len` and `ls.len >= 3` (stdlib `add` has no `ensures`), `ls.setLen(3)` does not give
`ls.len == 3`, `fbump(i)` gives nothing (no `ensures`: correct by the spec), and the case above. The first two
need the stdlib patches the spec PR announces; the last one needs the prover.
