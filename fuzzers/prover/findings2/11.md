# 11 — Facts about `var` parameters survive barriers that write them through an alias; facts about a global survive a store to a `var` parameter that aliases it

kind: **accepts-invalid (unsound)**. known-as: **new as a report**, but **expected**: 67c81be4's PR text says
"The prover on master has no owned/shared distinction" — this is the `var`-parameter half of that, which the
earlier reports do not cover (fuzzers#5 = globals/threadvars across a call, #4 = `addr`, #6 = captured locals).
Found by flavour A: 147 log lines (heuristic mapping in dedupe.csv), first after 4.4 s; five minimized
representatives (`raw/unsound_2026171983543_6`, `_2026171983339_33`, `_2026171983555_18`,
`_2026171983357_78`, `_2026171983684_5`).

## Minimized repro (`repro/r11_varparam_alias.nim`)

```nim
{.feature: "staticContracts".}
{.feature: "assumeSync".}
import std/syncio
type
  Obj = object
    f: int
    items: seq[int]
  Hold = ref object
    o: Obj
var g = 0
proc setG(v: int) = g = v
func shrink(o: var Obj) = o.items.setLen(0)

proc a(n: var int; arr: array[4, int]): int =     # fact about a `var` param, a call writes it
  result = 0
  if n >= 0 and n < 4:
    setG(1000000000)              # `n` is `g` here
    {.assert: n < 4.}             # accepted
    result = arr[n]               # accepted: no check left

proc b(o, q: var Obj): int =                      # fact about one `var` param, a func writes the other
  result = 0
  if o.items.len > 0:
    shrink(q)                     # `q` is `o` (same object behind two refs)
    {.assert: o.items.len > 0.}   # accepted
    echo "len after shrink(q): ", o.items.len
    result = o.items[0]           # accepted: no check left

proc c(n: var int; arr: array[4, int]): int =     # fact about a global, a store to a `var` param
  result = 0
  if g >= 0 and g < 4:
    n = 1000000000                # `n` is `g` here
    {.assert: g < 4.}             # accepted
    result = arr[g]               # accepted

let arr = [1, 2, 3, 4]
g = 1
echo "c: ", c(g, arr)
g = 1
let h1 = Hold(o: Obj(items: @[7]))
let h2 = h1
echo "b: ", b(h1.o, h2.o)
echo "a: ", a(g, arr)
```

Command: `bin/nimony c -r --nimcache:nc r11_varparam_alias.nim` (each of `a`, `b`, `c` also run alone).

Actual: compiles. `c` and `a` each die with a segmentation fault (exit 139, `arr[1000000000]`); `b` prints
`len after shrink(q): 0` and then `7`, read from `o.items[0]` of an empty seq without a check. With
`{.feature: "runtimeContracts".}` and the asserts removed: `index out of bounds: 1000000000 notin 0..3`.
The call-site alias check does not apply: `b(h1.o, h2.o)` goes through two refs, `c(g, arr)` passes a global.

Expected: `cannot prove assertion` and the index checks kept. doc/language.md, Aliasing: "Every other variable is
**shared**: a `var`, `out` or `lent` parameter, a global ... What is known about it holds until the next
*barrier* that does not name it." "A **barrier** is ... a call to a `proc` ... a store whose target is not an
owned variable: ... to a global, or to a `var` parameter." "Only when the variable handed over is itself shared
is the call [to a func] a barrier."

Other barrier kinds confirmed by the generator and by hand (`work2/probe/a1.nim`), all accepted with a fact that
fails at run time: method call (`poke(gb, v)` writing a global), call through a global routine value
(`gfn(v)` writing a threadvar), a callee storing through a pointer stashed earlier (`stash(addr x)` then
`pokeP(v)`: address-taken local, same family as #4), closure call writing a captured local (#6), direct stores
`go.f = v` / `gv = v` invalidating a `var` param that aliases them.

## Phase / function at fault

`src/nimony/contracts_fir.nim: analyseCallArgs` and the code after it: after a call only `mutatedRoots` (the
arguments bound to `var`/`out` formals) lose their facts; for a store, only facts about the stored location.
Nothing models a `var` parameter (or a global) as shared.

Fix risk: high in effect (the planned implementation of the spec): facts about `var` params across `proc`
calls stop being proved, so code that indexes with a `var` param after a call needs a local copy.
