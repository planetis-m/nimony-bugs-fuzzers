# 02 — `shr` of a negative constant is folded toward zero (`(-1) shr 1 == 0`); the prover proves indexes from the wrong value

kind: **accepts-invalid (unsound)**, and a constant-folding **miscompile** on its own. known-as: **new**.

## Minimized repro (`repro/r02_negshr.nim`)

```nim
{.feature: "staticContracts".}
import std/syncio
const K = (-1) shr 1              # folded to 0
proc f(): int =
  var arr = [10, 20, 30, 40]
  let k = (-2) shr 2
  echo "k = ", k                  # -1 at run time
  {.assert: k >= 0 and k <= 3.}   # accepted
  result = arr[(-2) shr 2]        # accepted: reads arr[-1]
var one = 1
echo "const ", K, " runtime ", (-1) shr one
echo f()
```

Command: `bin/nimony c -r --nimcache:nc r02_negshr.nim`

Actual:

```
const 0 runtime -1
k = -1
4203174
```

Expected: `K == -1` (signed `shr` is arithmetic at run time, as the output shows), the assertion reported as
violated and `arr[-1]` rejected (`{.feature: "runtimeContracts".}` gives `index out of bounds: -1 notin 0..3`).
Fuzzer shapes: `takesRT((-2) shr 2)` and `o.cnt = (-2) shr 2` for a `range[0..8]` target.

## False fact derived

`(-2) shr 2 == 0` (the program computes `-1`), so `0 <= (-2) shr 2 <= 3`.

## Rule at fault

`src/nimony/xints.nim: shr` shifts the magnitude and keeps the sign (`neg: a.neg, val: a.val shr b`): that rounds
toward zero, while an arithmetic shift rounds toward minus infinity (`-1 shr 1` gives "-0"). It is used by
`src/nimony/expreval.nim` (`of AshrX: evalShiftOp(c, n, shr)`, comment "xints.shr keeps the sign the same, so has
ashr behavior for signed ints") — the `const K` half — and through `tryEvalOrdinal` by
`src/nimony/contracts_fir.nim: foldOrdinal`, which `checkInRange` and `proveCond` use for constant operands.
`foldWraps` only distrusts `+ - * neg shl`, not `shr`.

Phase: constant evaluation (xints), consumed by the prover.
