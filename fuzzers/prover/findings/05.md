# 05 — Facts about a global survive a call that writes the global

kind: **accepts-invalid (unsound)**. known-as: **new**. Found by a hand probe during the run (the generator had no
globals; they were added afterwards as `FUZZ_EXTRA=globals`, see README).

## Minimized repro (`repro/r05_global.nim`)

```nim
{.feature: "staticContracts".}
{.feature: "assumeSync".}
import std/syncio
var g = 0
proc setg() = g = 1000000000
proc f(): int =
  var arr = [1, 2, 3, 4]
  result = 0
  if g >= 0 and g < 4:
    setg()                    # writes the global
    {.assert: g < 4.}         # accepted
    result = arr[g]           # accepted: no check left
echo f()
```

Command: `bin/nimony c -r --nimcache:nc r05_global.nim`

Actual: compiles; the program dies with a bus error (exit status 135) reading `arr[1000000000]`.
The same happens without either feature when the accesses are wrapped in `{.cast(assumeSync).}:` (default mode
removes the check too), and for a global object field / global seq (`go.f < gs.len`, callee does
`gs.setLen(0)`, then `gs[go.f]`).

Expected: `cannot prove assertion: g < 4` and `cannot prove 'g' is in range 0..3`: `setg` is a `proc`, not a
`func`, so it may write any global.

## False fact derived

`0 <= g < 4` after `setg()`.

## Rule at fault

`src/nimony/contracts_fir.nim: analyseCallArgs` and the code after it (lines ~4510-4525): after a call only
`mutatedRoots` (arguments bound to `var`/`out` formals) lose their facts, and `mutatesUnknown` drops *derived*
locations (`invalidateAllDerived`). Nothing drops the facts keyed on a `gvar` when the callee is not a `func`
(not `noSideEffect`). The nil analysis already refuses globals as roots (`analysableRoot`: "assume sharing of
global variables between threads" returns `NoSymId` for `GvarY`); the arithmetic fact engine
(`getVarId`/`plainLocationVarId`) has no such exclusion.
