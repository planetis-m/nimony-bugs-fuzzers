# 01 — After a `for` loop that contains `break`, only the `break` path is believed: the "iterator finished / never entered" exit is dropped

kind: **accepts-invalid (unsound)** — top severity. known-as: **new** (not in bug-reports; upstream #2765 is a different `for` problem and is closed).

## Minimized repro (`repro/r01_forbreak.nim`)

```nim
{.feature: "staticContracts".}
import std/syncio

proc find(s: seq[int]; x: int): int =
  var idx = -1
  for k in 0 ..< s.len:
    if s[k] == x:
      idx = k
      break
  {.assert: idx >= 0.}      # false when x is not in s
  result = s[idx]           # index "proven": no run-time check is left

echo find(@[10, 20, 30], 20)
echo find(@[10, 20, 30], 99)
```

Command: `bin/nimony c -r --nimcache:nc r01_forbreak.nim`

Actual: compiles; prints `20` then `0` (reads `s[-1]`). Without the feature line and the `{.assert.}` the program
is accepted too and also prints `0`: the bounds check is removed in the default mode as well.
With `{.feature: "runtimeContracts".}` (assert line removed) the second call stops with
`seqimpl.nim(239, 41): 0 <= i [AssertionDefect]`.

Expected: `cannot prove assertion: 0 <= idx` and `cannot prove contract: i < s.len and 0 <= i`, as for the same
search written with `while k < s.len: ...; break; ...; inc k` (rejected, checked).

Other shapes of the same bug (all confirmed by hand):

* `repro/r01_forbreak_empty.nim`: `for k in 0 ..< s.len: (if s[k] == 3: break)` then `s[0]` is accepted and
  segfaults on an empty seq; `for k in 0 ..< n: break` then `{.assert: n > 0.}` is accepted for `n = 0`.
* `repro/r01_forbreak_contradiction.nim` (what the fuzzer hit first): `for k in 2 .. 0: break` leaves the
  contradictory facts `2 <= k <= 0` behind, after which any claim about a value with a constant bound is proved:
  `inc(o.cnt, 2)` on a `range[0..8]` field holding 8 (prints `cnt=10`) and `arr[int(o.cnt)]` on a 3-element array.

## False fact derived

After the loop: every fact that holds at the `break` (the iterator's range `lo <= k < hi`, hence `lo < hi`; the
condition guarding the `break`; assignments made before it). The path on which the iterator simply ends — or the
loop body never runs — contributes nothing.

## Rule at fault

* `src/nimony/controlflow.nim: trFor` lowers a `for` to `(ite (true) <body> <jmp exit>)`: the loop's ordinary
  exit is the else-edge of a constant-true condition, "because the iterator's termination test is not generated
  until hexer".
* `src/nimony/contracts_fir.nim: traverseIte` marks that else-arm dead (`if constCond == 1: c.tr.live = false`),
  so the exit jump records no state.
* `src/nimony/flowtracker.nim: bindLoopExit` handles the label: with no `break` it restores liveness on the
  pre-loop state (sound); with a `break`, `key in tr.exits` and `bindKey` runs with `tr.live == false`, so
  `setTo(fs, here, landed)` installs the `break` state alone instead of joining it with the pre-loop state.

Phase: contract prover (flow tracker), `bindLoopExit`/`bindKey`.
