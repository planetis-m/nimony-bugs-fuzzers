# 08 — In `except`/`finally` the prover believes the `try` body ran to its end

kind: **accepts-invalid (unsound)**. known-as: **new** (nothing in bug-reports; upstream title searches empty).
Found by a hand probe after the for/`break` bug (01) pointed at exit joins; the generator has no `try`.

## Minimized repro (`repro/r08_except.nim`)

```nim
{.feature: "staticContracts".}
import std/syncio
proc risky(x: int) {.raises.} =
  if x > 3: raise Failure
proc f(x: int): int =
  var arr = [1, 2, 3, 4]
  var y = 0
  result = 0
  try:
    y = x
    risky(x)                 # raises: control goes to `except` with y == x
    y = 0
  except:
    {.assert: y == 0.}       # accepted
    echo "in except, y = ", y
    result = arr[y]          # accepted: no check left
echo f(1000000000)
```

Command: `bin/nimony c -r --nimcache:nc r08_except.nim`

Actual: compiles; the program dies with a segmentation fault (no output). With
`{.feature: "runtimeContracts".}` and the assert removed it prints `in except, y = 1000000000` and stops with
`index out of bounds: 1000000000 notin 0..3`.

Expected: `cannot prove assertion: y == 0` and `cannot prove 'y' is in range 0..3`.

Also confirmed:

* `repro/r08_finally.nim`: the same body with `finally:` instead of `except:` — accepted, segfault.
* `repro/r08_raise_const.nim`: `y = 5; if x > 3: raise Failure; y = 0` then `except: {.assert: y == 0.}` is
  accepted and the handler prints `y = 5` and reads `arr[5]` of a 4-element array (garbage value printed).
* The mirror image is a wrong rejection: with `y = 5; risky(x); y = 0`, `except: {.assert: y == 5.}` — true
  whenever the handler runs — is reported as `assertion violated: y == 5`.
* Not reproduced: `var y = x; try: (if x > 3: raise Failure); y = 0  except: {.assert: y == 0.}` is rejected
  ("cannot prove"), so an explicit `raise` does carry *some* state; why the constant case above differs is
  unverified.

## False fact derived

At the entry of the handler: the facts that hold after the last statement of the `try` body (`y == 0`), instead
of the join over every point of the body that can raise.

## Rule at fault (best reading, partly unverified)

`src/nimony/controlflow.nim: trTry` — the only jumps into the `except` bodies are `thisBlock.breakInstrs`,
which `trRaise` (and `return`) fill; a *call* to a `.raises` routine produces no edge to the handler. The prover
(`contracts_fir.nim` via `flowtracker.nim: bindRaise`/`bindKey`) therefore reaches the handler with the state it
has at that point of its walk. `bindKey` has the same "not live -> take the landed state alone" branch that causes
bug 01.
