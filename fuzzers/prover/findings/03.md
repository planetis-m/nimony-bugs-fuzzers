# 03 — `abs` promises `result >= 0` by `{.assume.}`; false for `low(T)`, so `abs(x)` indexes without a check

kind: **accepts-invalid (unsound)**. known-as: **new**. Found by a hand probe while the run was going (the
generator had no `abs`; `abs` was added to the expression grammar afterwards, the input domain already contains
`low(int)`).

## Minimized repro (`repro/r03_abs.nim`)

```nim
{.feature: "staticContracts".}
import std/syncio
proc f(x: int8): int =
  var arr = [1, 2, 3, 4]
  let y = abs(x)
  {.assert: y >= 0.}              # accepted; false for x = -128
  result = 0
  if y < 4: result = arr[int(y)]  # accepted: reads arr[-128]
var v = low(int8)
echo abs(v)
echo f(v)
```

Command: `bin/nimony c -r --nimcache:nc r03_abs.nim`

Actual: prints `-128` and then a garbage value (e.g. `12984`; it varies): `arr[-128]` is read unchecked.
With `{.feature: "runtimeContracts".}` (assert removed): `index out of bounds: -128 notin 0..3`.

Expected: `cannot prove assertion: 0 <= y` / the index reported as unproven — signed arithmetic wraps
(doc/language.md, "Signed overflow"), so `abs(low(T)) == low(T)`. Same for `int` (`abs(low(int))` prints
`-9223372036854775808`).

## False fact derived

`0 <= abs(x)` for every `x`.

## Rule at fault

Not the engine: `lib/std/system.nim: abs` (line 234) declares `ensures: not (result < T(0))` and discharges it
with `{.assume: not (result < T(0)).}`. `contracts_fir.nim: assumeEnsures` takes the callee's word at each call.
Either the contract needs `requires: x != low(T)` or the `ensures` must go.
