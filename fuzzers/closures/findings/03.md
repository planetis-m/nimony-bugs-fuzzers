# 03: A closure variable captured by another closure and also called by its owner: `could not find symbol: c2.0`

## Repro (`r03_captured_closure_var.nim`, file: findings/repros/r03_captured_closure_var.nim)

```nim
import std/syncio
type CT = proc (y: int): int {.closure.}

proc main(a: int) =
  var c2: CT = proc (y: int): int {.closure.} = y + 1
  let c: CT = proc (y: int): int {.closure.} =
    result = c2(a)
  echo c2(a)
  echo c(0)
main(4)
```

Command: `nimony c -r --nimcache:<dir> r03_captured_closure_var.nim` (nimony master 0305d6c6)

## Actual

```
[Bug] could not find symbol: c2.0
```

## Expected

`5` twice (`c2(4)` = 5, `c(0)` = `c2(4)` = 5)

## Phase at fault

hexer `lambdalifting` (pass 2, the rewrite of uses of a captured local): once `c2` moves into the environment, the owner's own direct call `c2(a)` still refers to the stack symbol `c2.0`, which no longer exists. Without the owner's direct call (`echo c2(a)`) it compiles. Most frequent campaign signature (f01, 399 of 2174 programs).

Kind: crash. Known-as: new (nim-lang/nimony#2378 is a closed sibling-closure nil-env bug, different shape) (checked ../bug-reports/*/report.md and `gh issue list -R nim-lang/nimony`).
