# 16: Closure iterator in a module whose file name starts with a digit: nifcore `module suffix expanded` assertion

## Repro (`1ci.nim`)

```nim
import std/syncio
iterator ci(): int {.closure, sideEffect.} =
  yield 1
for x in ci(): echo x
```

Command: `nimony c -r --nimcache:<dir> 1ci.nim` (nimony master 0305d6c6)

## Actual

```
Error: unhandled exception: nifcore.nim(654, 3) `s.len == 0 or s[s.len - 1] != '.'` a symbol reaches the pool with its module suffix expanded, never as `ci`coro.0.1ci3y4zi91`dy.0.`
```

## Expected

1

## Phase at fault

hexer `coro_transform`/`cps` build symbol names as `<name>`coro.0.<suffix>`; a module suffix starting with a digit is then parsed as part of the numeric disambiguator. Renaming `1ci.nim` to `ci1.nim` makes it work. Found by accident while saving repros.

Kind: crash. Known-as: new (checked ../bug-reports/*/report.md and `gh issue list -R nim-lang/nimony`).
