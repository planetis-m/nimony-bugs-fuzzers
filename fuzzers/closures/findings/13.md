# 13: SEGFAULT at run time: `.closure, raises` iterator with a `try/except` around an inlined loop, closures created in both the inline iterator and the handler

## Repro (`r13_closure_iter_try_inline_segv.nim`, file: findings/repros/r13_closure_iter_try_inline_segv.nim)

```nim
import std/syncio
type CT = proc (y: int): int {.closure, raises.}

proc mk(a: int): CT {.raises.} =
  result = proc (y: int): int {.closure, raises.} = a + y

iterator it(): int {.raises, sideEffect.} =
  for i in 0 ..< 3:
    var c: CT = mk(5)
  yield 1

iterator ci(): int {.closure, raises, sideEffect.} =
  for x in it():
    try:
      for y in it():
        discard
    except ErrorCode:
      var c: CT = mk(7)
  yield 2

proc u() {.raises.} =
  for x in ci():
    echo x

try:
  u()
except ErrorCode as e:
  echo "exc ", e
echo "end"
```

## Phase at fault

hexer `cps`/`coro_transform` frame layout for locals of inlined iterator copies (closure-typed `c` from both inlined copies of `it` plus the handler's `c`): a frame slot of closure type is read/destroyed uninitialized. Removing the handler's `mk(7)` or the inner loop makes it pass. Found by the campaign (f22-f24, seed 5144). The only run-time failure in 2174 programs.
