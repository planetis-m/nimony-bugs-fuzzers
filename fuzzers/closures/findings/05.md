# 05: Closure nested in a closure inside an inline iterator that is inlined twice: C `redefinition of anonproc`

## Repro (`r05_nested_closure_redefinition.nim`, file: findings/repros/r05_nested_closure_redefinition.nim)

```nim
import std/syncio
type CT = proc (y: int): int {.closure.}

iterator it(): int {.sideEffect.} =
  yield 1
  yield 2
iterator it2(a: int): int {.sideEffect.} =
  var c: CT = proc (y: int): int {.closure.} =
    var c2: CT = proc (y: int): int {.closure.} = y
    result = c2(y)
  yield c(a)
proc u() =
  for x in it():
    for y in it2(x):
      echo y
u()
```

Command: `nimony c -r --nimcache:<dir> r05_nested_closure_redefinition.nim` (nimony master 0305d6c6)

## Actual

```
error: redefinition of ‘X60Qanonproc_1_...’ (gcc)
```

## Expected

1, 2

## Phase at fault

hexer `iterinliner.collectDefs` (src/hexer/iterinliner.nim:338): a nested routine in a copied body gets a fresh `iir` name per copy, but "what it declares inside is its own and keeps its names" -- so the inner closure literal `c2` (a routine inside the routine) is emitted once per copy under the same global name. The body is copied twice because `it` yields twice.

Kind: crash (invalid C). Known-as: new (reports 80/102 are field-default redefinitions, different cause) (checked ../bug-reports/*/report.md and `gh issue list -R nim-lang/nimony`).
