# 06: Closure capturing a loop variable inside an inline iterator that is itself iterated by a `.closure` iterator: `Symbol not found in NIF module: iir`

## Repro (`r06_inline_iter_closure_in_closure_iter.nim`, file: findings/repros/r06_inline_iter_closure_in_closure_iter.nim)

```nim
import std/syncio
type CT = proc (y: int): int {.closure.}

iterator it(): int {.sideEffect.} =
  for i in 0 ..< 2:
    var c: CT = proc (y: int): int {.closure.} = y + i
    yield c(1)
iterator ci(): int {.closure, sideEffect.} =
  for x in it():
    yield x
for x in ci(): echo x
```

Command: `nimony c -r --nimcache:<dir> r06_inline_iter_closure_in_closure_iter.nim` (nimony master 0305d6c6)

## Actual

```
Error: unhandled exception: Symbol not found in NIF module: `iir.1001.<mod> [AssertionDefect]
```

## Expected

1, 2 (each line `y + i` = 1 then 2)

## Phase at fault

hexer `iterinliner.rewriteClosureIter` -> `transformStmt` inlines `it` into the closure iterator; the copied closure gets a fresh global `iir` name and `publish`es it, but the publication is lost on the closure-iterator path (the body is built in a side buffer `bodyBuf` and re-copied by `rewriteYieldsAndCopy`), so lambdalifting/cps look the name up and fail. Same inline iterator in a plain proc works.

Kind: crash. Known-as: new (checked ../bug-reports/*/report.md and `gh issue list -R nim-lang/nimony`).
