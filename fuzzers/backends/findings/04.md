# JS/wasm backend: a `case` whose selector is not `int` fails in jorogumo: "unsupported case label: TagLit"

Kind: rejects-valid (backend crash on valid code). Backends: JS (`nimony j`) and wasm (`nimony w`). Known-as: new.
Fuzzer: 26 programs on each of j and w.

Repro (`cs64.nim`; the `int8` program of finding 03 fails the same way):
```nim
import std/syncio
proc f(x: int64) =
  case x
  of 0: echo "zero"
  else: echo "other"
f(0'i64)
```
Command: `nimony j --nimcache:nc cs64.nim` (also `nimony w`).

Actual: `jorogumo: unsupported case label: TagLit` (exit 1). Expected: `zero` (C, LLVM, native).
Only `case` on `int` (and presumably char/enum) works: there the label stays a bare IntLit.

Phase: nativenif `src/web/codegen.nim` `caseValue` (~line 3170) accepts only `IntLit` and `CharLit` labels; for an
`int64`/`int8`/... selector nimony emits the label as a typed literal (`(suf ...)`/`(conv ...)` tag). `caseValue`
needs to look through `SufC`/conversion of a literal, as `genSufLit`/`sufFloatVal` already do for expressions.
