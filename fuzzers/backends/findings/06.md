# LLVM backend: `not` of an operation the optimizer folded to a literal is emitted as `i64` in an `int32` context: "'%t7' defined with type 'i64' but expected 'i32'"

Kind: crash (invalid IR, rejected by clang). Backend: LLVM (`nimony l`) with the optimizer (`-d:danger`/`--opt:speed`).
Known-as: new. Fuzzer: 9 programs.

Repro (`l2.nim`):
```nim
import std/syncio
proc t(p4: int32) =
  let x: int32 = not (p4 - p4)
  echo x
t(5'i32)
```
Command: `nimony l -d:danger --nimcache:nc l2.nim`

Actual: `l2....ll:62:13: error: '%t7' defined with type 'i64' but expected 'i32'` (the IR has `%t7 = xor i64 0, -1`).
Expected: `-1` (C with -d:danger; LLVM without -d:danger prints `-1`).

Phase: shoggoth folds `p4 - p4` to an untyped literal `0`; lengc LLVM lowers `bitnot` with the literal's default
type (i64) instead of the `not` node's own type (int32). The `not`/`bitnot` lowering in
`src/lengc/llvmgenexprs.nim` should take its type from the expression, not from a literal operand
(same class as finding 05: literal operands lose their type).
