# Native backend: `float64(x)` of a `uint64` ARRAY ELEMENT ≥ 2^63 converts it as signed (gives -2^63 instead of 2^63)

Kind: miscompile. Backend: native (`nimony n`, arkham x64), with and without `-d:danger`. Known-as: new.
Fuzzer: baseline difffuzz mismatches 500085 and 500184, extended-run 1000227.

Repro (`na.nim`):
```nim
import std/syncio
proc t(p0: uint64) =
  var arr: array[2, uint64] = [p0, p0 + 1'u64]
  let a = float64(arr[1])
  let b = float64(p0)
  echo cast[uint64](a), " ", cast[uint64](b)
t(0x8000000000000005'u64)
```
Command: `nimony n --nimcache:nc na.nim && nc/n/*/na`

Actual (native): `14114281232179134464 4890909195324358656` (0xC3E0000000000000 = -2^63, then +2^63)
Expected (C, LLVM, JS, wasm): `4890909195324358656 4890909195324358656`

The parameter converts correctly; the array element does not.

Phase: arkham `src/arkham/x64/value.nim` int→float conversion (~line 3398): it picks `fcvtI2F` (signed cvtsi2sd)
when `srcSigned or srcW < 64`, and `fcvtU2F` only otherwise. `g.srcWidthSigned(inner)` evidently reports the
`(at arr i)` operand as signed or narrower than 64 bits, so the unsigned path is skipped; it must use the element type.
