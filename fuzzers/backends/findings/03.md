# LLVM backend: `case` on an `int8`/`int16`/`int32`/`uint8`/`uint16` selector fails in clang: "case value is not a constant integer"

Kind: rejects-valid (backend crash on valid code). Backend: LLVM (`nimony l`), with or without `-d:danger`. Known-as: new.
Fuzzer: 27 programs (every program whose generator chose a narrow `case` selector; the generator then had to restrict
`case` to `int` selectors in 88% of programs to keep LLVM coverage).

Repro (`cs8.nim`):
```nim
import std/syncio
proc f(x: int8) =
  case x
  of 0: echo "zero"
  of 1, 2: echo "one or two"
  else: echo "other"
f(2'i8)
```
Command: `nimony l --nimcache:nc cs8.nim`

Actual: `cs8....ll:64:5: error: case value is not a constant integer` from clang; the IR is
```
  %t7 = trunc i64 0 to i8
  %t8 = trunc i64 1 to i8
  switch i8 %t6, label %L6 [ i8 %t7, label %L4  i8 %t8, label %L5 ... ]
```
Expected: `one or two` (C and native). `int64`/`int` selectors and literal RANGES (`of 3 .. 5`) work: a range goes
through `emitRangeCheck`, which accepts non-constant bounds.

Phase: lengc LLVM, `src/lengc/llvmgenstmts.nim` case lowering (~line 263): a single `of` value is generated with
`genExprLLVM(c, n, val)` and appended to `switchCases`; a label that reaches lengc as a conversion of a literal to the
narrow selector type becomes a `trunc` instruction, but `switch` needs constants. The label must be folded to an
`llIntTextC` constant of `switchVal.typ` (as the range path already does for `llvInt` bounds).
