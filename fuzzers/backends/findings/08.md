# Native backend: `uint16(not x)` with `x: int8` is not zero-extended: prints 18446744073709551614 instead of 65534

Kind: miscompile. Backend: native (`nimony n`), with and without `-d:danger`. Known-as: new.
Fuzzer: extended-run native mismatches 1000028 and 1000133 (`u16v` printed as a 64-bit value), 1000219 (`uint8`
local printed as 18446744073709551615); baseline 500003, 500094, 500180, 500208 (`uint32` locals printed above 2^32)
are the same symptom (narrow unsigned value whose upper register bits are not cleared), not each confirmed separately.

Repro (`nc.nim`):
```nim
import std/syncio
proc t(x: int8) =
  var u: uint16 = uint16(not x)
  echo u
t(1'i8)
```
Command: `nimony n --nimcache:nc nc.nim && nc/n/*/nc`

Actual (native): `18446744073709551614`. Expected (C, LLVM, JS, wasm): `65534`.
`uint16(x)`, `uint32(y)`, `uint8(y)` of negative values are right; the `not` result is computed at full register width
and the narrowing conversion to the unsigned type does not re-truncate it, so `echo` (which widens a `uint16` with a
plain move) prints the 64-bit value.

Phase: arkham x64 (`src/arkham/x64/value.nim`), narrow `bitnot` / conversion: a sub-64-bit unsigned result must be
zero-extended (`movzx`) when it is converted/stored, or `not` must produce a width-normalized value.
