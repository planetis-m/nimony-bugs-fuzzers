# 08: out-of-range shift/rotate/bit counts are truncated mod 256; integer literals >= 2^63 crash the reader; u64 literal rejected

- kind: accepts-invalid (counts), crash (literal), rejects-valid (u64 literal)
- known-as: new
1. `(sal (cast (u 16) (rdx)) 65536)` -> `66 c1 e2 00` (count silently 0; GNU as rejects, "operand type mismatch"). Also `(rcl (r15) 4294967296)` -> `49 c1 d7 00`. Immediate counts for ALU ops *are* checked ("immediate 1000 does not fit a 8-bit sub-width operation"), but the shift/rotate/bt emitters (`RolX64..`, `ShlX64..`, `BtX64..` in `instr.nim` ~1306/1376 and the `emitShl/emitShr/emitRol/...` helpers `encoder.nim` ~1025-1190) cast the count to a byte unchecked. Repro `repro/sal_count_trunc.nif`.
2. Any integer literal above 2^63-1 makes nifasm die with an unhandled exception instead of a diagnostic: `(mov (rax) 9223372036854775808)` -> `parseutils.nim(430) integerOutOfRangeError / Error: unhandled exception: Parsed integer outside of valid range [ValueError]`. Repro `repro/int_literal_crash.nif`. Source: NIF integer token parsing (`parseBiggestInt`-style) reached from the operand parser.
3. The valid spelling for imm64 >= 2^63 is a `u` literal, but `(mov (rax) 18446744073709551615u)` is rejected: "Unexpected operand kind (kind=UIntLit)". So `mov rax, 0xFFFFFFFFFFFFFFFF` has to be written `-1`. (`repro/uint64_literal_rejected.nif`.) Low priority.
