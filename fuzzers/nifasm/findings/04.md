# 04: `div`/`idiv` accept a divisor that lives in RDX (or uses RDX as address); the lowering zeroes/sign-extends RDX first

- kind: accepts-invalid (miscompile: divide by zero / wrong address)
- known-as: new (the check `checkFixedRegFree` is the intended guard; this is a hole in it)
- phase/function: `DivX64`/`IdivX64` in `genInstX64` (`src/nifasm/x64/instr.nim` ~1095/1116) emit `xor rdx,rdx` / `cqo` BEFORE reading the divisor operand. `checkFixedRegFree` (`src/nifasm/x64/operands.nim` ~1052) only rejects a *named variable* still bound to RDX; a raw `(rdx)` register operand, or a `(mem (rdx) ..)` / index-rdx address, bypasses it (the comment there even says raw operands bypass parseOperand's binding check). Not a lenient-only issue: the repro below is a strict proc.

Repro (strict proc, no `(lenient)`):
```
(.nif27)
(.index)
(stmts (proc :main.0 (params) (result) (clobber) (stmts (div (rdx) (rax) (rdx)) (mov (rdi) 0) (mov (rax) 60) (syscall))))
```
Same with `(div (rdx) (rax) (cast (u 64) (mem (rdx))))`, `(idiv (rdx) (rax) (rdx))`, `(idiv (rdx) (rax) (cast (u 64) (mem (rcx) (rdx) 8)))`.
- actual: `xor rdx,rdx ; div rdx` (division by zero, SIGFPE) / `cqo ; idiv rdx` / `xor rdx,rdx ; div [rdx]` (address is 0)
- expected: a diagnostic ("div clobbers RDX ..."), exactly what a variable bound to rdx gets: `[Error] div clobbers RDX, still bound to variable 'd.0'`. (A divisor in RAX is fine.)
Repro files: `repro/div_rdx_divisor.nif`. Fuzzer logs it as verdict `hazard` (28 hits). First at t=124s (program 2029).
