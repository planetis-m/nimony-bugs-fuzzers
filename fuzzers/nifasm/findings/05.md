# 05: an explicit narrow `(cast (u N) ...)` operand is silently ignored: the instruction is emitted at 64 bits

- kind: miscompile (accepts-invalid input, wrong-width code)
- known-as: new. (nativenif#201 and #207 are different: those are identical-register and shift-count-register rejects.)
- phase/function: the width-aware families (`add/sub/and/or/xor/cmp/test/mov/adc/sbb`, shifts, `inc/dec/neg/not`) use the cast to pick an operand size; the rows below never read it. Each row calls the 64-bit-only emitter: `MulX64`/`DivX64`/`IdivX64` (`instr.nim` 1063/1095/1116), `ImulX64` (1073, emits `emitImul`/`emitImulImm`), `RolX64..RcrX64` with CL count (1306), `BtX64..BtcX64` with immediate (1376, `emitBt` etc.), `PushX64` (1710), `Cvtsi2sdX64/Cvtsi2ssX64` (2272, always REX.W), and the mem-destination ALU forms where the source register's cast is ignored (mem width comes only from the cast on the mem operand).

Examples (nifasm bytes vs GNU as; all `.nif`/`.s` pairs in `repro/`):
| nifasm input | nifasm | GNU as |
|---|---|---|
| `(mul (cast (u 32) (rsi)))` | `48 f7 e6` mul rsi | `f7 e6` mul esi |
| `(div (rdx) (rax) (cast (u 8) (rax)))` | `xor rdx,rdx; div rax` | `div al` |
| `(imul (cast (u 16) (r11)) (cast (u 16) (r11)))` | `4d 0f af db` imul r11,r11 | `66 45 0f af db` imul r11w,r11w |
| `(rol (cast (u 32) (rcx)) (cast (u 8) (rcx)))` (also ror/rcl/rcr, u8/u16) | `48 d3 c1` rol rcx,cl | `d3 c1` rol ecx,cl |
| `(bt (cast (u 32) (r14)) 5)` (also bts/btr/btc, u16) | `49 0f ba e6 05` bt r14,5 | `41 0f ba e6 05` bt r14d,5 |
| `(cvtsi2sd (xmm1) (cast (u 32) (rcx)))` (and cvtsi2ss) | `f2 48 0f 2a c9` (converts all 64 bits) | `f2 0f 2a c9` |
| `(push (cast (u 16) (r9)))` | `41 51` push r9 | `66 41 51` push r9w |
| `(add (mem (rcx)) (cast (u 8) (rax)))` (any ALU op, mem without cast, narrower reg source) | `48 01 01` add qword [rcx],rax | `00 01` add byte [rcx],al |
| `(movzx (rax) (cast (u 16) (rax)) 8)`, `(movsx ...)` | N wins, cast ignored | cast width wins in GNU mapping |
Consequence: e.g. `mul`/`bt` on a 32-bit value reads the upper register half; `add [mem], r8` writes 8 bytes. Generated by arkham these are probably always 64-bit so it may be latent, but nifasm raw/`{.assembler.}` input accepts the cast and gives wrong code, with no diagnostic.
Mixed-width pairs that GNU as rejects but nifasm accepts are item 07.
First seen t=2s (program 36).
