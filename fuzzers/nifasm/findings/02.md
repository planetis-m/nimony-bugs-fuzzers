# 02: memory operand silently replaced by RAX (`.reg` of an `okMem` operand is read)

- kind: miscompile (operand silently dropped) and accepts-invalid
- known-as: new
- phase/function: `genInstX64` in `src/nifasm/x64/instr.nim`. These sites call `parseOperand(...)/parseDest(...)` and then use `.reg` without checking `kind == okReg`; for a memory operand `.reg` is the default (RAX), so the instruction assembles against rax and the address is dropped:
  - `Cvtsi2sdX64, Cvtsi2ssX64` (~2272): `let s = parseOperand(n, ctx).reg`
  - `Cvttsd2siX64, Cvttss2siX64` (~2281): `let d = parseDest(n, ctx).reg`
  - `MovfqX64, MovfdX64` (~2290): both `parseOperand(..).reg` and `parseDest(..).reg`
  - `Prefetcht0/1/2/ntaX64` (~2545-2560): `x86.emitPrefetchT0(.., op.reg)`
  An `if op.kind != okReg: error(...)` is missing at each site.

| nifasm input | nifasm bytes | GNU as for the intended instruction |
|---|---|---|
| `(cvtsi2sd (xmm6) (cast (u 32) (mem (r9))))` | `f2 48 0f 2a f0` = `cvtsi2sd xmm6, rax` | `f2 41 0f 2a 31` |
| `(cvttsd2si (cast (u 64) (mem (rax))) (xmm1))` | `f2 48 0f 2c c1` = `cvttsd2si rax, xmm1` (store into memory becomes a register write) | not encodable (dest must be a reg) so this is accepts-invalid |
| `(movfq (xmm2) (cast (u 64) (mem (rsp))))` | `66 48 0f 6e d0` = `movq xmm2, rax` | `f3 0f 7e 14 24` |
| `(movfq (cast (u 64) (mem (rsp))) (xmm2))` | `66 48 0f 7e d0` = `movq rax, xmm2` | `66 0f d6 14 24` |
| `(movfd (cast (u 32) (mem (rax))) (xmm1))` | `66 0f 7e c8` = `movd eax, xmm1` | `66 0f 7e 08` |
| `(prefetcht0 (mem (rax) 8))` (also t1/t2/nta) | `0f 18 c8` = `nop eax` (no prefetch, address ignored) | `0f 18 48 08` |
| `(prefetcht0 (rax))` | `0f 18 c8` (reg operand taken as an encoding, mod=11) | prefetch needs a memory operand |

Repros: `repro/cvtsi2sd_mem.nif`, `cvttsd2si_mem_dest.nif`, `movfq_mem_load.nif`, `movfq_mem_store.nif`, `prefetcht0_mem.nif`, `prefetcht0_reg.nif`, `prefetcht1_mem.nif`; run `findings/run_repros.sh`.
Found at t=2s (movfq/cvtsi2*, program 36) and t=20s (prefetch, program 255).
Note: the movfq/movfd/cvtsi2* mem forms are not documented (doc says "between gpr and xmm"), so the minimal fix is to reject them; dropping the address silently is the bug.
