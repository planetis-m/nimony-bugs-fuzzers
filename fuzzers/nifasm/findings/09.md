# 09: rejects-valid / known gaps (NOT counted as bugs)

These are the deliberate "not supported yet" sites hit by the fuzzer (GNU as accepts the input, nifasm reports a diagnostic). Class = diagnostic text, number of distinct signatures in 45 min:
- inc/dec/neg/not/pop/push on memory ("... memory not supported yet"), known as bug-reports/37 for inc/dec
- shifts/rotates with a memory destination ("Shift destination cannot be memory", "Rotate destination cannot be memory"), rcl/rcr "no sub-width form", rotate count other than imm/CL
- bt/bts/btr/btc with a non-register destination, bsf/bsr/popcnt/movzx/movsx with a memory source ("source must be a register")
- `test` with a memory operand or immediate ("TEST with memory operand not supported yet")
- `setcc` with memory ("SETcc memory not supported yet")
- `lea` with a non-register destination, 3-operand `imul` with a memory source
- `mov`/ALU with a narrow *register* destination written as `(mov (cast (u 8) (rax)) ..)` ("Expected memory destination": only add/sub/... allow it; the dest-cast form of mov accepts only a 64-bit register source); adc/sbb/xadd/cmpxchg/xchg register-register forms ("Expected memory destination", "adc needs a N-bit operand")
- packed SSE (`addpd/subpd/mulpd/addps/mulps/punpcklqdq`) with a memory source ("expected xmm register or float variable"), `movsd/movfq` shapes
- `lock xchg/btc/bts/btr/adc/sbb/cmpxchg8b` ("Unsupported instruction for LOCK prefix")
- `mov [mem], imm` with an imm that needs 64 bits ("Immediate too large for memory move"; correct, x86 has no such form)
- nativenif#201 (`and/or/sub r, r` with identical registers) does not reproduce in `(lenient)` raw procs; it needs an `{.assembler.}` variable-bound proc, not covered by this fuzzer.
Oracle note: immediates that do not fit a sub-width operation (`add al, 1000`) are rejected by nifasm and silently truncated by GNU as (binutils gives no warning: `xor al, -129` becomes `xor al, 0x7f`); asmfuzz counts them as ok.
