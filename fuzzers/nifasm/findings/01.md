# 01: `(cmpxchg8b <mem>)` encodes CMPXCHG16B (REX.W set)

- kind: miscompile
- known-as: new (no nativenif issue, no bug-reports entry)
- phase/function: nifasm x64 encoder, `emitCmpxchg8b` (both overloads, `src/nifasm/x64/encoder.nim` ~1602 and ~1615): `var rex = RexPrefix(w: true)`. The dispatch is `Cmpxchg8bX64` in `genInstX64` (`src/nifasm/x64/instr.nim` ~2505). The comment in the mem overload even says "With REX.W this is actually CMPXCHG16B".

Repro (`repro/cmpxchg8b.nif`):
```
(.nif27)
(.index)
(stmts (proc :main.0 (params) (result) (clobber) (lenient) (stmts (cmpxchg8b (cast (u 64) (mem (rax)))))))
```
Command: `nifasm -o:out repro/cmpxchg8b.nif; objdump -d -M intel out`
- actual: `48 0f c7 08  cmpxchg16b OWORD PTR [rax]` (16-byte compare-exchange, needs 16-byte alignment, faults with #GP otherwise, CPUs without CX16 raise #UD)
- expected (GNU as `cmpxchg8b qword ptr [rax]`): `0f c7 08`
Register form (`(cmpxchg8b (rax))`) is accepted too; it has no encoding (ModRM mod=11 /1 is invalid) and should be rejected.
Found by fuzz at t=51s (program 770).
